Понятное описание проекта pipeline_vkr
1. Что это за проект и зачем он нужен

Этот проект — это небольшой Python-пайплайн для анализа результатов молекулярной динамики (MD).
Его задача — взять готовые файлы траектории и топологии, прочитать их, посчитать несколько обязательных характеристик белка и его участков, а затем сохранить результаты в виде таблиц и графиков.

В проекте реализован только обязательный минимум по заданию:

RMSD
RMSF
radius of gyration (Rg) во времени
residue-wise contribution to Rg
SASA
построение графиков
запуск через CLI-команду python run_pipeline.py ...

Важно: этот пайплайн не охватывает весь старый репозиторий целиком, а только ту часть, которая нужна для обязательных пунктов 1–6. Это прямо отражено в README: optional extensions и более широкие ML/topology части сюда не входят

Простыми словами: что делает проект

На вход подаются:

файл топологии *.tpr
файл траектории *.xtc
YAML-файл с описанием областей белка, которые нужно анализировать
папка, куда сохранить результаты

После запуска пайплайн:

считывает конфиг с областями;
загружает траекторию;
проверяет, что области корректны;
выравнивает траекторию по C-alpha белка;
считает обязательные метрики;
сохраняет CSV-файлы;
строит PNG-графики.
Для чего это нужно

Идея проекта — не смотреть на траекторию вручную, а получить готовые численные характеристики и графики для:

всего белка;
отдельных доменов;
выбранного эпитопа.

Это позволяет сравнивать поведение разных частей структуры в динамике.

2. Что именно считается в проекте

Ниже — простое описание каждой метрики.

RMSD

RMSD показывает, насколько структура в каждом кадре отклоняется от исходного состояния.
В этом проекте RMSD считается после глобального выравнивания траектории по protein and name CA, а результат записывается в нанометрах

RMSF

RMSF показывает, насколько сильно колеблется каждый остаток.
Здесь RMSF считается только по C-alpha атомам, тоже в нанометрах

Rg (radius of gyration)

Rg показывает, насколько компактна или растянута структура.
Если Rg меняется, это может означать изменение общей формы области белка.
В проекте считается временной ряд Rg для каждой области в нанометрах

Residue-wise contribution to Rg

Это приближённая оценка того, какие остатки сильнее вносят вклад в распределение массы относительно центра масс.
Важно: в README специально написано, что это approximation, а не единственная строго каноническая формула

SASA

SASA — это площадь поверхности, доступной растворителю.
В проекте SASA считается с помощью mdakit-sasa, отдельно для каждой заданной области, и сохраняется в nm².
При этом SASA не собирается из атомных вкладов полной структуры, а считается отдельным selected analysis по каждой области

3. Основная идея работы пайплайна

Если объяснить совсем по-человечески, то внутренняя логика такая:

Прочитать YAML-файл с описанием областей.
Загрузить tpr и xtc как MDAnalysis.Universe.
Убедиться, что в каждой области вообще есть атомы.
Убедиться, что в каждой области есть C-alpha атомы, иначе RMSF посчитать нельзя.
Выполнить выравнивание траектории.
Посчитать RMSD.
Посчитать RMSF.
Посчитать временной ряд Rg.
Посчитать residue-wise contribution to Rg.
Посчитать SASA.
Записать CSV.
Построить графики.
4. Структура проекта: какие файлы есть и что они делают

Ниже перечислены главные файлы, которые реально нужны для понимания и запуска.

run_pipeline.py

Это главная точка входа.
Именно этот файл запускается из терминала командой:

python run_pipeline.py --tpr ... --xtc ... --config ... --output ...

Что он делает:

принимает аргументы командной строки;
вызывает загрузку конфига;
загружает Universe;
запускает валидацию;
запускает выравнивание и все расчёты;
записывает CSV;
вызывает построение графиков.
modules/config.py

Этот файл отвечает за чтение YAML-конфига с областями.
Он:

проверяет, что файл существует;
читает список regions;
проверяет, что у каждой области есть name и selection;
запрещает пустые и дублирующиеся имена областей.
modules/loader.py

Этот файл отвечает за загрузку входных файлов.
Он:

проверяет существование tpr и xtc;
создаёт MDAnalysis.Universe.
modules/validation.py

Этот модуль делает проверки перед расчётом:

что selection для каждой области не пустой;
что в каждой области есть C-alpha атомы, иначе RMSF не посчитать.

Если здесь ошибка, значит обычно проблема в YAML selection.

modules/rmsd.py

Здесь логика RMSD и глобального выравнивания.

Что важно:

выравнивание делается по protein and name CA;
используется fit_rot_trans;
это было сделано вместо старого тяжёлого пути, который мог вызывать OOM;
потом RMSD считается для каждой области по всем кадрам.
modules/rmsf.py

Считает RMSF по регионам.

Что важно:

RMSF считается по C-alpha атомам;
результат возвращается как пары (resid, rmsf_nm).
modules/rg.py

Здесь считаются:

Rg во времени;
residue-wise contribution to Rg.

Что важно:

временной Rg считается по каждому кадру и каждой области;
residue-wise contribution — это именно приближение, а не “абсолютно стандартная” формула.
modules/sasa.py

Считает SASA.

Что важно:

используется mdakit-sasa;
для каждой области запускается отдельный SASAAnalysis(...).run();
итог берётся как analysis.results.total_area;
значения переводятся из Å² в nm².

Именно этот модуль обычно работает дольше всего и часто печатает предупреждения FreeSASA.

plot.py

Этот файл строит графики:

временные ряды;
RMSF по остаткам;
residue-wise contribution to Rg.
requirements.txt

Список зависимостей, которые нужно установить:

MDAnalysis>=2.6
matplotlib>=3.8
numpy>=1.26
PyYAML>=6.0
mdakit-sasa
regions.example.yaml

Пример конфигурации областей, которые анализируются.
Сейчас там три области:

full_protein
extracellular_domain
epitope_323_337
README.md

Краткое официальное описание пайплайна:

scope проекта;
пример запуска;
какие выходы формируются;
в каких единицах измеряются результаты;
важные оговорки по SASA и residue-wise contribution to Rg.
Остальные старые материалы репозитория

В репозитории могут лежать старые ноутбуки, артефакты и материалы из предыдущих этапов проекта.
Они не обязательны для запуска именно этого пайплайна. README прямо говорит, что такие исторические материалы оставлены как reference artifacts

6. Что именно передаётся через YAML-конфиг

Файл regions.example.yaml содержит список областей белка, которые нужно анализировать.
У каждой области есть:

name — имя области;
selection — selection string для MDAnalysis.

Текущий пример:

regions:
  - name: full_protein
    selection: "protein"
  - name: extracellular_domain
    selection: "protein and resid 233-360"
  - name: epitope_323_337
    selection: "protein and resid 323-337"

Если понадобится анализировать другие области, можно сделать свой YAML по такому же шаблону.

Важно:

имя области не должно быть пустым;
selection не должен быть пустым;
имена областей не должны повторяться;
selection должен реально выбирать атомы, иначе пайплайн упадёт на валидации.

10. Какие warning'и допустимы

В этом проекте допустимы предупреждения от FreeSASA, если run всё равно доходит до конца.

Например, сообщения вида:

FreeSASA: warning: atom ... unknown, guessing element ...
предупреждения про несовпадение residue SASA

Они неприятные, но не обязательно критичные, если:

sasa_*.csv созданы;
plots/sasa.png создался;
нет Traceback.

Это связано с тем, что библиотека может не идеально распознавать некоторые имена атомов, но итоговый total SASA по region при этом всё равно рассчитывается.

11. Что делать, если запуск падает
Если ошибка Config file not found

Значит неверный путь к YAML-файлу.
Нужно проверить аргумент --config.

Если ошибка TPR file not found или XTC file not found

Значит неверный путь к входным файлам.
Нужно проверить --tpr и --xtc.

Если ошибка про selection returned 0 atoms

Значит в YAML указан некорректный selection, который не выбирает ни одного атома.

Если ошибка про has no C-alpha atoms for RMSF

Значит в выбранной области нет C-alpha атомов, а RMSF в этом проекте считается именно по ним.

Если SASA идёт очень долго

Это возможно на больших траекториях.
SASA — самая тяжёлая часть пайплайна, потому что запускается отдельно по каждой области.

12. Что не нужно коммитить в репозиторий

В репозиторий не нужно класть:

временные output-папки;
локальные результаты проверок;
большие траектории;
.venv;
временные .xtc и другие большие generated-файлы.

Логика .gitignore именно такая: большие MD-файлы, окружения, логи и временные результаты должны быть исключены из Git

То есть папки вроде:

acceptance_run_final/
out_md_*
временные .xtc

обычно не надо пушить.

14. Итоговое понимание проекта в одном абзаце

Этот проект — это простой и узко сфокусированный MD-analysis pipeline для обязательной части задания.
Он запускается одной CLI-командой, читает траекторию и YAML с областями, валидирует входные данные, выравнивает траекторию, считает RMSD, RMSF, Rg, residue-wise contribution to Rg и SASA, а затем сохраняет результаты в CSV и PNG. Основные файлы, которые реально важны для понимания, — это run_pipeline.py, папка modules/, plot.py, requirements.txt, regions.example.yaml и README.md
